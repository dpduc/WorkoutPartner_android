# Guests get every feature, and their data stays on-device

Guests can now use everything an Account can — including Roster, Quick Count, Tallies, Weekly Target and Streak Shields, which were previously Account-only — so the only thing an Account adds is cloud backup and multi-device sync. We kept Guest data purely local and extended ADR-0004's one-time claim step (now covering Tracked Profiles, Tallies, Weekly Target and Shields) rather than switching to Firebase Anonymous Auth, which would have given every Guest a real uid, synced from day one, and replaced the claim step with `linkWithCredential`. Anonymous Auth was rejected because it doesn't work under `LocalAuthGateway` (no Firebase configured) and would have discarded the already-working claim path. Consequence: signing in to an *existing* Account while holding Guest data can't be handled silently — the Guest is asked to merge (Account's Weekly Target wins, Streak is recomputed over the merged history) or discard (permanent delete, after showing what will be lost); backing out cancels the sign-in so data is never left ownerless.
